# Dify Cloud 本地 API 联调记录

## 已验证

- Cloudflare 官方便携工具下载超时，未采用该路线。
- 使用 Windows OpenSSH 与 localhost.run 建立临时 HTTPS 隧道。
- 测试 API 只监听 `127.0.0.1:18765`，只提供 `/probe` 固定 JSON，不读取业务数据或文件。
- 本地和公网地址：缺少凭据返回 401，正确 Bearer 凭据返回 200 与 `connection_success`。
- 初次测试 API 在受限执行环境中启动，主机进程不能连通；切换到主机网络环境后复测通过。
- 没有调用模型。

## 最终状态

- 用户截图确认 Dify Cloud HTTP 节点：正确凭据返回 200、错误凭据返回 401。
- 地址变化后完成复测；SSH 多次重置，长期稳定性未通过。
- 测试 API 与 SSH 会话已终止；历史配置仅作测试记录。
- 浏览器自动化初始化失败；Dify 端证据来自用户截图，不能声称由助手自动操作。

## 复现

在普通主机 PowerShell 窗口、项目根目录执行 `python tools/tunnel_probe.py`。
随后在另一个主机终端使用 SSH 临时隧道指向 `127.0.0.1:18765`。
凭据保存在 `.local/tunnel-probe/token.txt`，每次服务启动重新生成。
当前 Dify 配置见 `.local/tunnel-probe/DIFY-HTTP-SETUP.txt`；其中临时 URL 只对当前会话有效。
不能把过期配置当作长期环境设置。

正式开发时进程都应在同一个主机网络环境运行。临时隧道仅用于联调，长期演示另行选择部署方式。

Dify 截图已证实正确凭据 HTTP 200；错误凭据首次填写到 header 名称失败，纠正后因 SSH 隧道连接被重置而中断，尚未获得 Dify 401。隧道重建后命令行再次验证错误凭据 401、正确凭据 200。临时隧道稳定性不足，不能作为长期地址。

最终验收：用户 Dify Cloud HTTP 节点截图确认正确凭据返回 200，错误凭据 Bearer wrong 返回 401（0.646 秒、0 token）。最小链路与鉴权通过。多次临时地址失效和 SSH reset 表明稳定性不满足长期运行要求；不宣称稳定性验收通过。测试完成后已请求终止测试 API 和 SSH 会话，当前地址不再用于后续调用。

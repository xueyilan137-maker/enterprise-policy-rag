# 业务网页与人工复核演示

日期：2026-10-22。入口 `http://127.0.0.1:18082/`，与原业务API同源，由FastAPI提供静态HTML/CSS/JavaScript；无需Node构建、额外容器、隧道或外部字体。Dify两应用仍各自第4版、提取协议1.0.2，未修改提示词、知识库或规则标准。

## 当前能力

员工选择演示身份后上传Markdown/文本PDF说明与CSV明细，查询真实异步提取状态，逐字段查看原文引用与行/页定位。只有validated记录显示创建申请入口；服务端仍独立核验，不能靠修改页面放行。已创建申请可发起规则预审，查看本人分页列表、问题、金额事实、制度正文、原始材料、运行轨迹与独立复核记录，并下载JSON或使用浏览器打印。

财务演示身份查看分页申请列表和受角色限制的材料/提取/报告详情；仅对已completed且有报告的申请记录复核。结论为reviewed（已核对，待后续处理）、needs_materials、follow_up，不存在批准金额或付款动作。操作者和时间来自服务端，报告结果原始字符串SHA-256与job_id关联。每份预审报告只保存一次，唯一约束/事务防止并发重复；同幂等键同内容返回原记录，换内容或对已复核报告再提交409。暂不提供改写、撤销、追加或更正复核功能。

制度条款由现有原创制度源渲染，只有当前源快照哈希与报告一致时展示该版本引用正文。这是规则报告条款对照，**不是新增RAG检索**；历史源已改变时提示人工核对，不误展示为历史依据。制度知识助手保留链接，在已有Dify发布页打开，未新增业务后端Chat API。

## 会话与权限边界

本机演示公开提供员工DEMO-001、财务FINANCE-DEMO两个视角选择，任何能访问该本机入口的人都能切换，**不是正式登录、身份核验、财务授权体系或生产安全验收**。旧后端Bearer凭据不下发网页；现有DEMO-002仅用于API隔离测试，保留原配置。角色在服务端固定映射，不接收任意员工ID或role；财务不能调用员工创建/上传接口，员工不能调用财务列表/详情/复核接口。

随机会话Cookie使用HttpOnly、SameSite=Strict，8小时过期，内存保存；切换和退出撤销旧会话，业务进程重启后重新选择身份。HTTP本机Cookie无Secure标记，HTTPS才设置，不能把该方案搬到公网。Cookie写请求及/web会话写请求要求精确同源Origin；旧Bearer客户端保持兼容。Host仅回环/测试主机，服务仍只绑定127.0.0.1:18082。

静态资源不包含Dify/规则/演示Bearer密钥；原始上传不在静态目录。材料、模型引用、复核备注均以DOM文本呈现，不解释材料HTML。CSP限制脚本/样式/请求为同源，响应no-store。会话/CSRF措施不能弥补开放角色选择的演示边界；正式认证、权限配置/审计、更正流程及资源隔离仍待实现。

## 接口与持久化

- `POST /web/session`：profile=employee/finance；`DELETE /web/session`退出。
- `GET /v1/applications?limit=30&offset=0`：本人申请，最多100/页。
- `GET /v1/extractions`：本人最近20项，复用已有GET详情和上传/提取/申请/预审接口。
- `GET /v1/review-queue`、`GET /v1/review-applications/{id}`：财务角色。
- `POST /v1/review-applications/{id}/reviews`：decision、note（5–2000字符）、Idempotency-Key；拒绝额外身份、金额或快照字段。
- `GET /v1/policies/{version}`：当前制度源、条款及源快照哈希。
- `/examples/`仅允许两份固定原创MD/CSV样例；`/assets/`仅web目录。

SQLite v3→v4只新增reviews表。启用前备份`.local/business/before-web-v4.sqlite3`，旧七表逐行哈希保持、完整性ok及外键零异常，证据`.local/evidence/web-migration-backup.json`、`web-migration-check.json`。后续新申请/提取/复核是验收追加记录，不覆盖旧业务数据。仍为单进程单worker，不是生产队列。

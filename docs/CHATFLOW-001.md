# 最小制度问答闭环验收

当前发布状态已由CHATFLOW-002取代；本文保留首版验收记录。

日期：2026-10-21。Dify 1.17.1，通义插件0.2.23，生成模型qwen3.7-flash，temperature=0.1。仅合成制度、本地演示；不是完整业务交付。

## 已实现与真实验证

原生Chatflow：开始 → Python日期/版本路由 → 保存待补问题 → 版本条件分支 → 对应知识库检索 → LLM生成JSON → Python引用成员校验 → 回答。日期缺失或无唯一版本直接回答，不调用生成模型。知识库沿用现有两版，不重复创建；top_k=3、不启用重排和阈值。

通过Dify界面导入生成的DSL，检查清单无错误，预览六轮真实运行：

| 输入 | 实际观察 |
|---|---|
| 餐费每天上限是多少？ | 追问完整出差开始日期 |
| 同会话补充2026-08-01 | 保留原问题，回答每天100.00元，引用TRAVEL-v2-MEAL |
| 2026-03-01出差，餐费每天上限是多少？ | 每天80.00元，引用TRAVEL-v1-MEAL |
| 2027-01-01去北京住宿标准？ | 无唯一适用制度，转人工，不套最新版 |
| 2026-08-01出差，公司婚假有几天？ | 依据不足拒答 |
| 2026-03-01去上海住宿，每人一晚最多多少钱？ | 上海A类、每晚500.00元，引用v1-LODGE与v1-CITY |

最后一条与BASELINE-001原查询的日期表达不同，不能据此声明CITY漏召回已修复。检索对比另见RETRIEVAL-EXPERIMENT-001。

已在本地实例发布第1版，并通过发布后的聊天页面真实复测v2餐费问答，得到100.00元及v2-MEAL出处。Dify生成的链接遗漏18080端口，使用同一路径补端口访问成功。实例绑定127.0.0.1，不是公网发布。

私有证据：`.local/evaluations/chatflow-smoke-001.json`、`chatflow-published-001.txt`，截图`.local/evidence/chatflow-published.png`。应用ID与演示URL保存在`.local/chatflow-state.json`，不要重复导入创建应用。

## 重建

`python tools/build_chatflow.py`输出不含真实知识库ID的`dify/policy-chatflow.template.yml`。JSON为合法YAML，已通过Dify导入验证。`python tools/build_chatflow.py --bind`从已有私有knowledge-state读取ID，生成`.local/policy-chatflow.bound.yml`，只写本地文件，不联网、不新建知识库。新环境先重建知识库并配置通义0.2.23与模型凭据，再生成绑定DSL。依赖列表为空表示不自动安装插件，不表示无需通义插件。

节点代码来自本项目`src/chatflow_nodes.py`，不是第三方应用DSL；官方1.17.1源代码只用于核对节点字段。公开模板中无Key、Header、实际dataset ID或环境URL。完整新环境重建尚未验收。

## 边界

- 日期仅解析完整年月日（YYYY-MM-DD、YYYY/M/D、YYYY年M月D日）；相对日期、只有年月、多日期均要求补充。不会自动猜出差开始日。
- 仅保存待补日期的问题；没有长期记忆，也不自动沿用上一问题日期。仅日期回复可补前问，新问题替换待问内容。
- 引用校验验证本轮检索内容包含条款ID、版本正确及JSON结构；不能证明模型回答每句话均被条款蕴含，仍需人工审核与独立保留集。
- 原生“引用和归属”展示的是检索来源，拒答时也可能显示差旅文件；不能把该来源卡片当作婚假问题有依据。正文拒答不附已验证条款。后续自建页面需区分检索来源和实际答案依据。
- 模型/知识库不可用会显示Dify运行失败，不回退mock；真实超时、401、429及对抗注入回归尚未完成。
- 本轮未统计生成token、费用或正式正确率；14项无模型工程测试通过，不能替代模型效果评测。

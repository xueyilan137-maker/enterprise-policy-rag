## 样例与独立性边界

`data/eval/reserve-v1/`包含8条问答、8份申请输入、独立gold.json、空human-reviews.json、逐项REVIEW.md、EXPOSURE.md及manifest.json。输入与参考标签均由助手原创合成并源文初核，尚未人类审核；没有用当前模型/规则输出反向生成标签。8+8仅第一批候选，不冒充方案目标40条问答/16份申请保留集。

问答覆盖规则跨费用误用、供餐与缺凭证、住宿夜数与期限组合、境外分类、整体通过边界、明细缺失、多轮无效日期修复及验真/付款边界。申请覆盖混合住宿交通、多夜住宿超额一分钱、交通缺事前批准、缺凭证、提交早于结束、凭证跨类别重复、未声明地域及两个明确总额冲突。

新输入与旧开发/联调样例、pilot无逐字重复；同一九类制度及已有工程/开发语义家族明显重叠，尤其A02/A03/A04，并非所有家族全新。逐项接触关系见EXPOSURE.md。准确称谓是“同域新输入的前瞻性确认评测候选”，不是第三方盲测、未见知识/OOD或严格语义家族完全隔离的独立测试集。若需声称未见场景泛化，应另立版本并事先审查家族接触史，不能靠换ID/城市/金额证明独立。

`data/eval/pilot-v1/`只有P01普通二等座正常链路、P02费用日期早于行程的服务端拦截，明确是开发数据，不与候选集混算。不得将试跑2/2解释为模型提取准确率或正式预审效果。

## 冻结与防止误用

`manifest.json`冻结输入、gold、审核单、接触史、生产源码、网页、公开DSL、制度/语料、开发集及评测主工具哈希；记录两个应用版本元数据及提取模型。变更受检文件后计划/运行停止，不能原地覆盖manifest。已有首次冻结不重复生成；样例/标签修订应新建版本并重新审核，不暗改当前候选。

冻结的是本机文件与当时私有部署状态记录，**不是对Dify实时图、运行镜像和配置的不可篡改证明**。材料运行另外核对返回的extractor_version；正式运行前仍须核对当前发布配置/模型和知识库参数。审核记录和私有证据不在不可变文件清单，靠每条input+gold哈希及证据哈希绑定；这也是本机人工声明流程，不是身份认证或第三方审计。

问答、检索、材料三个入口均要求对应标签已有真实人类批准记录，否则在HTTP客户端创建/模型调用之前停止。已实测当前16项全待审核，未产生保留任务或运行标记。材料与检索首次运行使用排他标记，失败/超时不自动重试，不覆盖首轮报告；问答回放模板和评分结果也不覆盖。已有样例一旦用于调参，应转开发数据并新建候选版本，不能继续当未见保留数据。

## 三条测量轨道

1. **检索诊断**：`tools/evaluate_reserved_retrieval.py`按冻结代码确定最终轮次版本，对实际版本隔离Dify知识库调用city-hint主检索top3，必要时同版REVIEW补1条。分别记录主Recall@3、最多4条合并覆盖、跨版和HTTP失败。失败/未运行在请求总数覆盖分母中保留；不是发布Chatflow端到端回答成绩。请求至少间隔7秒，无重试，不新建知识库。
2. **发布问答回放**：现无新增Chatflow服务密钥，继续复用已有发布网页，不为评测创建凭据。`tools/evaluate_qa.py template`在标签审核后生成私有逐轮问题/回答/页面证据表。必须逐例新会话按原问法回放，保留逐轮原回答、私有快照哈希及generated/evidence_excerpt/refused等实际可核验模式；没有日志确认就写unknown。`score`仅自动统计正文条款提及覆盖和跨版提及；不是实际召回率、引用蕴含或回答正确率。回答语义需人类逐点判断，未审核时分数为null，不能让条款ID出现就算答对。
3. **材料端到端**：`tools/evaluate_system.py reserve --pack reserve-v1`走真实业务HTTP上传MD/CSV→已发布模型提取→服务端核验→创建或422拦截→已发布规则Workflow→真实持久化报告。模型输入只含材料，gold和人工审核声明不发给模型。报告记录原始候选/核验、任务及运行ID、是否新任务、耗时；正式运行出现已有缓存不算新测量，不自动重跑。

材料case_pass核对核验状态、必要问题码、实际创建边界；可创建时还核对制度版本、预审状态、Decimal合计与完整问题集合。问题按(code, item_ids, clause_ids)多重集比较，不能只比问题码；记录微观TP/FP/FN，重复输出计FP。失败仍进入整体case分母；precision/recall分母为零保留null。核验候选的所有字段语义准确率、真人财务结论均未测，字段分数保留null。输出中“报告事实合计正确”也不代表票据真实。

## 人工审核怎么继续

先阅读`data/eval/reserve-v1/REVIEW.md`中的每项输入、参考答案/问题和制度原文，不要用应用当前输出来决定标签。请反馈需要更正的ID与依据；如果确已逐条核对且全部正确，可明确回复“16项已逐条审核，无需更正”。助手不能代替你作真人审核或把默认同意填成已审核。

实际人类结论到达后，原话保存为`.local/evidence/`的私有文本，再运行`tools/record_evaluation_review.py --ids <明确的逗号分隔ID> --reviewer <真实审核者标签> --evidence-file <实际私有证据文件>`记录声明。该工具不验证人的真实身份，操作方必须保证原话确来自人类；不运行工具就不会产生批准记录。若标签需要修订，当前冻结版本保留，另建版本、审核后再测。

标签审核是项目AGENTS要求区分助手初核与真实人类审核的落实，不是再次请求浏览器或模型使用权限。工具与两份调试验收已完成，剩余依赖真实的人类判断；即使标签通过，问答输出的语义评分仍需要看到回答后另做人工标注。

常用命令（工作目录为本项目）：

```powershell
.venv/Scripts/python tools/evaluate_system.py plan --pack reserve-v1
.venv/Scripts/python -m unittest discover -s tests
# 已冻结，勿再次freeze。pilot可复查但可能复用缓存，不作新模型成绩。
.venv/Scripts/python tools/evaluate_system.py pilot --pack pilot-v1
# 以下在相应人工标签审核后才可开展：
.venv/Scripts/python tools/evaluate_system.py reserve --pack reserve-v1
.venv/Scripts/python tools/evaluate_reserved_retrieval.py
.venv/Scripts/python tools/evaluate_qa.py template
```
